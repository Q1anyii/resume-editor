# 简历编辑器 · AI 对齐 JD（2026-11-19）

## 需求

在可视化简历编辑器（`简历编辑器.html`）里加 AI 能力：

1. 支持导入第三方 API Key（默认 DeepSeek，OpenAI 兼容端点）
2. 自带简历改写提示词
3. 按 JD 调整简历内容
4. 支持「一键全简历修改」或「指定模块对齐 JD」
5. 模块卡片上也要有入口，不只在侧栏面板里

## 方案要点

**不做「AI 直接覆盖原文」**。模型只输出结构化 `changes`，前端渲染成逐条 diff（旧文灰字删除线 / 新文绿底 / 理由），可单条「采用 / 忽略」，也可「全部采用 / 全部忽略」。AI 出错时不污染简历本体。

**事实边界三重锁死**：

1. 只把「措辞类字段」交给模型——`meta.summary`、`edu.text`、`project.desc/stack/bullets[].label/text`、`intern.bullets[].label/text`、`list.text`、`para.text`。姓名、联系行、时间行、项目名、公司名与角色一律不进清单。
2. 系统提示词写死 8 条规则：不新增项目/技术/数字/时间；不把「熟悉」升「精通」；项目甲 无 plan-and-execute 且只有它公网部署；摘要必须推销句、不以学历开头、≤110 字；bullet 40–110 字一个动作一个结果；只用 JD 出现过的能力词；技术栈只可重排；整份最多 12 条 changes 防输出截断。
3. 前端 `sanitizeChanges` 兜底：path 必须在输入清单、同 path 只取第一条、去空去重、长度 ≤260、过 `AI_BLOCKLIST`（plan-and-execute / 任务规划 / 任务分解 / 多步规划 / 两个项目均部署 / 已公网部署）。

**隐私**：Key 只存 `localStorage`，导出配置时 `delete snap.ai.key`；导入配置时沿用本机已存 Key。

## 实现

- 左栏「排版调节」之后新增 `#panelAi`：Base URL / 模型 / API Key（password，可折叠）/ 目标 JD / 改写范围 select（整份 + 各可见模块）/ 生成按钮 / 结果区
- 每个模块卡片头新增 `✦` 按钮（`data-act="aiScope"`）：选中该模块 → 滚到面板 → Key 与 JD 齐全则直接跑
- `collectFields(scope)` 生成字段清单，`runAi(scope)` 拼 user message（JD 原文 + 范围 + 带 path 的清单）
- 请求：`POST {baseUrl}/chat/completions`，`response_format: json_object`，`max_tokens: 8192`
- 状态码映射成人话：401 Key 无效 / 402 余额不足 / 429 太频繁 / 404 端点不存在 / 5xx 服务端异常
- 解析失败提示「不是 JSON（可能被截断）」，网络失败区分 CORS / 网络

## 踩到的坑

1. **`max_tokens` 初值 4096 有截断风险**。整份简历 40+ 字段，中文输出按 token 近似 1:1，4096 会切掉 JSON 尾部导致解析失败。改为 8192，并在提示词里限制「整份最多 12 条 changes」。
2. **编辑期两次误删上一轮代码**。替换 `if(act === 'up' || act === 'down'){` 时把 `const idx = state.order.indexOf(id);` 一起删掉；改 `/* 拖拽排序 */` 段首时把 `let dragId = null;` 删掉。都在后续编辑里补回，最终自测 `starBtn` / 拖拽回归通过。
3. **`renderEditor` 重建后结果区会空**。在 `renderEditor()` 末尾补 `renderAiResult()`，让 `aiResult` 在重绘后恢复显示。
4. **AI 配置输入不该触发预览重绘**。`input` 事件里对 `ai.` 前缀路径短路成只 `save()`，避免改 Base URL 时简历闪一下。

## 验证

- 浏览器跨域实测：本地 `file://` 页面向 `https://api.deepseek.com/chat/completions` 发真实 POST，拿到 `401` 与服务端 JSON 错误体（`Authentication Fails, Your api key: ****test is invalid`），说明浏览器可直连、无需代理，401 分支能读到真实信息。
- 注入自测 32 项全 OK：面板与字段存在、Key 输入为 password、模块 `✦` 数量与模块数一致、`collectFields` 全量与范围过滤、事实字段被锁定、`parseAiJson` 兼容 ``` 包裹、`sanitizeChanges` 拦截红线与非法 path 与超长与重复、请求 URL / Auth 头 / json_object / max_tokens=8192、系统提示含红线与 12 条上限、user message 含 path 清单、diff 渲染数量、附注渲染、单条采用写回、全部采用写回、采用后仍单页、401 提示、非 JSON 提示、导出不含 Key、默认配置正确。
- 截图核对：面板与模块卡片 ✦ 布局正常；3 条合规建议渲染成 diff 卡，3 条违规（plan-and-execute、两个项目均部署、改姓名）全部被拦下未显示。

## 已知限制

- 未用真实 API Key 跑通过完整链路（用户未提供），只能靠 mock fetch 验证「解析 → 校验 → diff → 采用 → 写回」。
- 依赖端点的 CORS 回显 Origin。换非 DeepSeek 端点前需重测预检。
- `response_format: json_object` 非所有 OpenAI 兼容端点都支持，遇到 400 会显示服务端原文。
- 采用 AI 建议后只做超页检测（状态栏变红），不会自动压缩回一页；需要用户自己删 bullet。
