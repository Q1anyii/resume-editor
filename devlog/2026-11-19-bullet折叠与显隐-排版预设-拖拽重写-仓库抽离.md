# bullet 折叠 / 显隐、4 套排版预设、拖拽重写、独立仓库

日期：2026-11-19
文件：`简历编辑器.html`（本轮起本仓库独立于 `tools/`）

## 需求

1. 项目（含实习）里的每条 bullet 支持折叠，长简历不必一直全展开。
2. 每个模块、每条 bullet 都能隐藏 / 显示，隐藏的不进预览和 PDF（不是删掉，是投不同岗位时临时关掉）。
3. 多做几套排版；**主题颜色要和排版解耦**，同一套配色能套到任意排版上。
4. 现在的模块拖拽体验差：drop 后整栏重绘、闪一下、滚动位置归零、也看不出会插到哪。
5. 把编辑器与 `devlog/` 从 `tools/` 抽出来，单独建一个仓库，去掉固定路径之类不可移植的东西。
6. 「AI 对齐 JD」面板不能滚动：JD 框跟着内容越长越高，建议多了把左栏撑得很长。

## 方案

### 1. bullet 折叠

- 状态键 `f:b:<模块id>:<条目序号>:<bullet序号>`，沿用已有的 `isFold / toggleFold / foldBtn`，`state.ui` 落库，刷新后仍在。
- bullet 渲染时把 label / text 两个字段包进 `.bullet-body`；折叠是 `.bullet.collapsed .bullet-body{display:none}`，只留一行头。
- 收起后认不出是哪条，所以在头行加 `.bullet-peek`：露 label（没有就露正文）前 20 字，超长省略号。

### 2. bullet 隐藏

- bullet 上存 `visible: false`（不初始化，缺省即显示，兼容老数据和导入的 JSON）。
- 头行三个按钮：`◉ / ○` 显隐、`▾ / ▸` 折叠、`✕` 删除。
- 预览渲染时 `(it.bullets||[]).filter(b => b.visible !== false)`，两处（project / intern）都过滤。标题行写「· 已隐藏」，卡片虚线 + 半透明。
- 模块的隐藏本来就是 `m.visible`，这次只补了 `renderRail()`：隐藏 / 删除 / 上下移 / 拖拽之后，左侧跳转条要跟着改，原来会不同步。

### 3. 排版预设（与主题解耦）

```js
const LAYOUT_PRESETS = [
  { id:'standard', layout:{ fs:9.3,  lh:1.55, gap:10 } },
  { id:'compact',  layout:{ fs:8.8,  lh:1.42, gap:7  } },
  { id:'loose',    layout:{ fs:10.0, lh:1.72, gap:13 } },
  { id:'airy',     layout:{ fs:9.0,  lh:1.85, gap:16 } }
];
```

- 预设只写 `--fs / --lh / --gap` 三个变量，`editorW` 不动；配色走 `applyTheme()` 的另一组变量，两者天然独立。
- 排版面板顶部四个按钮，当前预设高亮；点过滑块就置 `preset='custom'` 并清掉高亮（手动微调不该继续冒充某个预设）。
- 旧的 `state.layout` 没有 `preset` 字段，`loadState` / 导入配置 / 恢复默认三处都补了 `preset:'standard'`。

### 4. 拖拽重写：HTML5 DragEvent → pointer 事件

旧方案的问题：`dragstart/dragover/drop` 三套（模块、条目、bullet），drop 后 `renderEditor()` 全量重绘 → 闪、丢滚动、没有落点提示。

新方案一套引擎，三处共用：

- 手柄 `pointerdown` 即进入拖动（手柄不是按钮，不需要移动阈值）；`document` 监听 `pointermove / pointerup / pointercancel`。
- 每次 move 遍历同列表的兄弟元素，指针落在某元素上半 → 插它前面；全部落在下半 → 末尾。
- 目标位置画一条 3px 蓝色 `.drop-line`（fixed 定位，按目标矩形算 left / width / top），指哪插哪。
- `body.sorting` 时 `user-select:none`、抓手 cursor 改 grabbing；被拖元素 `.dragging` 半透明。
- 拖到左栏上下边缘 64px 内自动 `scrollTop ± 14`，长列表能拖到底。
- 松手才算索引：`from → to`，`to = from < targetIdx ? targetIdx-1 : targetIdx`（先抽走自己再插到目标前），然后 `splice` 一次、重绘一次。
- 三处统一 `applySort(s, from, to)`，落数据后 `renderEditor / renderPreview / checkOverflow / applyZoom / renderRail / save`。
- 顺手把 `renderEditor()` 改成先记 `editorEl.scrollTop`、`innerHTML` 之后再写回。折叠、显隐、拖拽、增删条目都会重绘，不还原滚动位置的话每次点按钮都会被弹回顶部。

### 5. AI 面板滚动

- `.ai-jd` 固定 96px 高、`overflow-y:auto`，`autoGrowAll()` 与输入事件里都跳过它（原来自动增高会把 JD 框顶成几百像素）。
- `#aiResult` 限高 340px + `overflow-y:auto`，细滚动条。建议再多也不会把面板撑长。

### 6. 抽离仓库

- 新仓库 `resume-editor/`：`简历编辑器.html` + `devlog/` + `README.md` + `.gitignore`。
- 编辑器内部本来就没有硬编码 Windows 路径（`Select-String 'D:\\|D:/|file:///'` 零命中），所以主要是把文档里的引用改成仓库内相对路径：devlog 里 6 篇的 `` `tools/简历编辑器.html` `` 改为 `` `简历编辑器.html` ``。
- `tools/` 侧删除这两个条目（`git rm`），README 里编辑器的整节改为指向 `../resume-editor/`；Python 版式脚本留在 `tools/`。

## 踩坑

1. **`draggable="true"` 会和 pointer 拖拽打架**：HTML5 拖影一旦启动，`pointermove` 就收不到连续事件。必须把所有 `draggable` 属性删干净，只留 pointer 一条路。
2. **`sorter.to` 不能用 `null` 同时表示「还没判定」和「落到末尾」**：用 `undefined` 表示未判定、`null` 表示末尾，否则单击手柄不移动时也会误判成末尾插入。
3. **`--dump-dom` 重定向到文件得走管道**：PowerShell 里 `& chrome ... > file` 得到 0 字节；改成 `& chrome ... 2>&1 | Out-File -FilePath <file> -Encoding utf8` 才拿到完整 DOM。另外必须给独立 `--user-data-dir`，否则和已开着的 Chrome 打架。
4. **headless 截图里 `scrollIntoView` 不生效**：左栏滚动没发生，截出来永远是顶部。改用 `document.getElementById('editor').scrollTop = 1500` 硬设，要看的区域才进画面。
5. **模块跳转条不会自动跟随**：`renderRail()` 只在 `renderEditor()` 末尾调用，而 `up/down/delModule/toggle/applySort` 里是「先改 state 再 renderEditor …」→ rail 其实会重绘；但 `addModule` 与拖拽顺序在这轮之前漏了，这轮统一补上调用，避免跳转条顺序和实际顺序不一致。
