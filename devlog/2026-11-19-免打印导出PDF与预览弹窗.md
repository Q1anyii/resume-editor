# 2026-11-19 免打印导出 PDF（大窗口预览 + 确认后直接生成）

## 需求

不用系统打印对话框，点一下直接得到 PDF 文件；导出前先给一个大窗口展示整页预览，用户确认后再导出。

## 方案

### 顶栏按钮分工

原来的「导出 PDF」= 开系统打印，本次把它拆成两条路径：

| 按钮 | 行为 |
|---|---|
| 导出 PDF（`btnPdf`，主按钮） | 打开预览弹窗 → 确认后 html2canvas 截 A4 页 + jsPDF 合成 → 直接 `pdf.save()`，全程不弹打印窗口 |
| 打印 · 矢量（`btnImgPdf`，改名） | 仍走 `window.print()`，输出矢量 PDF |

原「图像版 PDF」按钮被主按钮吸收，不再单独存在。位图路径与打印路径的差别在弹窗底部明说：位图 240dpi、文字不可选中；要 ATS 能读的矢量版走「打印 · 矢量」。

### 为什么没有做「纯前端出矢量中文 PDF」

jsPDF 内置字体不含中文。要在浏览器里排版出矢量中文，必须把整套中文 TTF 塞进 PDF：`addFileToVFS` + `addFont` 不做子集化，单个 Noto Sans SC 就 10MB 量级，一份简历带 10MB 字体不可接受；纯前端也没有可用的字体子集化工具。所以默认路径是高位图（240dpi），矢量留给打印。

### 预览弹窗

`#pdfModal` 是一个覆盖全屏的 `.modal`，里面 `.modal-box` 高度 `min(92vh, 1320px)`、宽 `min(1080px, 94vw)`。

打开时把 `#page`（右侧真实 A4）的 `innerHTML` 与 9 个排版/主题变量（`--fs --lh --gap --accent* --ink-*`）克隆到 `#pdfModalPage`，所以预览就是导出结果的等比缩略，改的是副本、碰不到真页面。

缩放 `fitPdfPreview()` 按舞台可用宽高算比例，`transform-origin: top left` 缩放，外面 `.modal-wrap` 用缩放后的像素尺寸占位，避免滚动条按未缩放尺寸算：

```
s = min((stageW-36)/794, (stageH-36)/1122, 1.8)
```

窗口 resize 时重算（`applyZoom()` 之后追加 `fitPdfPreview()`）。ESC 或点遮罩关闭。

### 导出流程改造

`exportImgPdf()` 复用原有的 `buildExportBox()`（临时隐藏顶栏/主体、把 A4 盒落到文档 (0,0)），改动：

- `scale` 2 → 2.5（A4 宽 794px × 2.5 = 1985px ≈ 240dpi）
- 生成中的 loading 挂到弹窗的 `#pdfConfirm`（原来挂在已删除的顶栏按钮）
- 成功 → `done(true)`：恢复舞台 + **关闭弹窗**；失败 → `done(false)`：恢复舞台、弹窗留着让人重试
- 文件名从 `姓名 + 完整 jobTitle`（会带出「｜可提前到岗实习」）改为 `姓名 + 岗位`，岗位按 `｜` 前段切
- `buildExportBox()` 的隐藏列表加上 `#pdfModal`，否则全屏遮罩会盖在导出盒子上

## 踩过的坑

- **jsPDF 的 `save` 挂在实例上，不在原型上**。自测想拦下载，改 `window.jspdf.jsPDF.prototype.save` 无效（`pdfDone` 一直是 false，但文件名、页数又都对得上，因为真的保存了）。正确做法是用 `Proxy` 包一层构造函数，在 `construct` 里拿到实例后覆写 `inst.save`。
- headless 里 `--dump-dom` 的输出会先落盘、进程却不一定退出；本次实测写完 173KB 的 DOM 后 chrome 仍有 7 个子进程挂着。用 `Start-Process` + `WaitForExit(ms)` + 按 `--user-data-dir` 过滤后 `Stop-Process` 收尾，否则后续命令会被卡住。
- 4.5 秒不够：`scale 2.5` 的 1985×2805 canvas 在 headless 下生成要更久，第一次自测 `pdfDone=false`。等待放到 9 秒才稳定。
- 「导出后界面空白一两秒」是这个方案固有的：导出期间顶栏与主体被 `display:none`，从点击到 canvas 生成完都看不到界面，所以状态提示只能放在弹窗按钮上。

## 验证

headless Chrome（1400×1000）+ 注入自测脚本：

- 预览：弹窗打开；`#pdfModalPage.innerHTML` 与 `#page` 逐字一致（长度 3804）；`wrap` 460 × 650、`transform: scale(0.5788)`（舞台 1080×686，符合 `min(...)` 计算）；状态文本「单页 · 余 12pt」、class `st`（非超页的红字）
- 确认导出：PDF 1 页、页面 210.0 × 297.0mm、文件名 `张三-IT 工程师（开发方向）.pdf`、`console.error` 空
- 导出后：弹窗关闭、`.main` 的 `display` 恢复 `flex`、`#pdfConfirm` 文案复位
- 再打开 + ESC：弹窗正常关闭
- 分辨率：同一取景配置下 canvas 实测 1985 × 2805（240dpi，与 `794 × 1122` 的盒子和 `scale 2.5` 吻合）

## 已知限制

- 位图 PDF 文字不可选中，招聘系统的文本解析可能读不到内容；正式投递仍建议「打印 · 矢量」。
- `scale 2.5` 在低配机器上可能占到数百 MB 内存、生成耗时 2–5 秒，没有做降级重试。
- 内容超过一页时按页高切片分页，切点落在文字行中间会把这行切断（与上一版行为一致，未改）。

## 追加：文件名统一为「姓名-求职意向-简历」

原来 PDF 存成 `姓名-完整岗位行.pdf`，岗位行里的「｜可提前到岗实习」会一起进文件名；HTML 那边则是 `姓名-岗位-简历.html`，两套不一致。现在统一：

```
[meta.name, jobTitle.split(/[｜|]/)[0].trim(), '简历'].filter(Boolean).join('-') + '.pdf'
```

实测文件名：`张三-IT 工程师（开发方向）-简历.pdf`（岗位行原文 `IT 工程师（开发方向）｜可提前到岗实习`）。姓名或求职意向为空时该项自动略过，不会出现 `--` 或孤零零的「简历-简历」以外的怪组合。
