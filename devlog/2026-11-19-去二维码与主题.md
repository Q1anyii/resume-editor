# 2026-11-19 · 去二维码 + 左右宽度 + 主题 + tools 独立仓库

## 需求

1. 用户已手工改过一版简历，去掉了两个二维码，把 GitHub 与作品站并进联系行。编辑器默认渲染要与其对齐。
2. 增加「左右两个板块宽度可调」。
3. 多提供几套主题与配色。
4. 把 `tools/` 单独拆成一个 git 仓库。

## 改动

### 去二维码

- 删除 `qrcode-generator` 的 CDN 引用、`drawQr()`、`stripProto()`（只被二维码说明文字用过）
- `state.meta` 只剩 `name / jobTitle / contact / summary`，`qrGithub / qrWeb / showQr` 全部移除
- 左栏「个人信息」去掉两个二维码输入框与「显示二维码」勾选
- 删除 `.qr-wrap / .qr-item / .qr-slot / .qr-cap / .qr-empty` 全部样式

旧快照仍带着这些字段，但 `renderPreview()` 已不看它们，无需迁移。

### 联系行合并

默认数据改成与用户手改后的样式一致：

```
jobTitle: IT 工程师（开发方向）｜可提前到岗实习
contact : 意向：城市/全国 ｜ 13800000000 ｜ you@example.com ｜ GitHub: github.com/yourname ｜ 作品：example.com
```

宽度核算：去掉二维码后内容区全宽约 695px（A4 210mm，左右各 13mm 内边距），这行实测单行占据 `h = 18px = 1 行`，正好铺满，不再换行也不再被裁。

### 左右宽度

- `state.layout.editorW`（px，300–860），`.editor{width:var(--editor-w,430px)}`
- `--editor-w` 写在 `document.documentElement` 上，由 `setEditorWidth()` 统一 clamp
- 中间加 `.splitter`（7px，`cursor:col-resize`，hover 变主色竖线），`pointerdown/move/up` + `setPointerCapture` 拖动；上限取 `min(860, innerWidth - 430)`，避免把预览挤没
- 「排版调节」里多一条「左栏宽度」滑块，与分隔条共用 `applyLayout()`
- 打印时 `.splitter` 隐藏；窗口 <1100px 变上下布局时也隐藏

### 主题

- 简历渲染样式全量变量化：`--accent / --accent-deep / --accent-strong / --accent-bg / --ink-main / --ink-sub / --ink-soft`
  （原来散在 `.r-title / .r-h2 / .r-h3 / .r-code / .r-strong / .r-ul li::before / .r-a` 里的硬编码色号一并替换）
- `THEMES` 8 套：经典深蓝、石墨黑、墨绿、酒红、石板蓝、暖褐、深青、黛紫
- `applyTheme()` 只改 `pageEl` 上的变量，不重绘；切换主题后 `renderEditor()` 刷新选中态
- 主题只作用于 A4 简历本体，编辑器外壳配色不变

## 两个坑

### 1. 打印时宽度测量失真

自测在 `--print-to-pdf` 环境下读 `editorW`，拿到 764px 而不是 430px。原因：打印视口是 A4 宽 794px，命中 `@media (max-width:1100px)`，`.editor{width:100%}` 覆盖了变量。

不影响产品（真实窗口 1600px 下 `.editor` 宽度实测随变量变化，360 / 430 / 600 三档截图核对），但暴露了媒体查询顺序问题：`@media print` 原本写在 `(max-width:1100px)` 之前，打印时后者会盖掉前者。已把 `@media print` 移到后面，并显式补 `.preview{height:auto}`。

### 2. `--dump-dom` 在本机拿不到输出

`chrome --headless --dump-dom` 经 PowerShell 捕获到的 stdout 长度为 0（新旧 headless 都试过），管道和 `>` 重定向都一样。

改用「页面自证 + PDF 提取」：自测脚本把结果写进一个 `position:fixed` 的白底 `<pre>` 块，跑 `--print-to-pdf`，再用 `pymupdf` 从第一页文本里找 `SELFTEST`。既能拿到断言值，也顺带验证了打印通道本身（页数、尺寸、行数）。
