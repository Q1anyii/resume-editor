# 2026-11-19 导出 HTML

## 需求

把当前编辑状态导出一份「干净的简历 HTML」：不是把编辑器自身另存，而是一份可以直接双击打开、可以当附件投递的简历网页；并且这份文件还能被本工具的「导入 HTML」原样读回来继续改。

## 方案

### 导出：语义化 HTML + 内联样式

顶栏新增「导出 HTML」（`btnExportHtml`），点一下生成字符串、走 Blob 下载，文件名 `姓名-岗位-简历.html`（岗位取求职意向里 `｜` 之前那段）。

`exportHtmlSource()` 按 `state.order` 顺序生成语义结构，刻意和导入器的识别规则对齐：

```
h1 姓名
p.r-title   求职意向：…
p.r-contact 联系行（自动 linkify，网址变 <a>）
p.r-summary 个人摘要（**加粗** 还原成 <strong>）
h2.r-h2     每个可见模块的标题
  ├ 教育：p.r-p「学校 ｜ 专业 … ｜ <code>时间</code>」
  ├ 项目：h3 项目名 → p.r-meta「meta<br><span.r-code>技术栈</span>」→ p.r-desc → ul.r-ul
  ├ 实习：p.r-p「<strong>公司</strong> ｜ 岗位 ｜ <code>时间</code>」→ ul.r-ul
  ├ 技能（列表）：ul.r-ul，条目小标题用 <strong class="r-strong">…</strong>：
  └ 段落：p.r-p
```

- bullet 的 `label` 必须写成 `<strong>` + 冒号，导入器就是靠「li 首个 strong 且紧跟冒号」认小标题的
- `visible === false` 的模块和 bullet 一律不写进文件，与预览、PDF 保持一致
- 样式用 `EXPORT_CSS`（从预览的 `.r-*` 规则抄一份成为独立样式表），字号 / 行距 / 模块距 / 主题色按当前 `state.layout` 与 `state.theme` **写死**成 `.resume` 上的 CSS 变量，出去的文件与屏幕上看到的一致；另外带 `@page{size:A4}` 与打印媒体查询，直接 Ctrl+P 也能出干净的 A4
- 不引外部字体、不引 CDN，断网双击也能正常显示

### 导入器：改成按文档顺序遍历

原来的 `parseResumeHtml` 用 `doc.body.firstElementChild` 沿兄弟链往下走，简历外面只要套一层 `<main>` / `<div>` 就整段读不到（导出的文件正是 `<main class="resume">`）。

改成先 `doc.body.querySelectorAll('h1,h2,h3,p,ul,ol')` 取全部语义节点、再按文档顺序过一遍状态机；头部那 3 个 `p` 也改成从 `nodes` 里 h1 之后、第一个 `h2` 之前收集。顺带修好了另一种外部简历：每段被 div 包起来的也能读了。

## 踩过的坑

- **probe 注入打错位置，误报「功能没实现」**：注入脚本用 `s.replace('</body>', inj + '</body>')` 只替换第一个匹配，而 `exportHtmlSource()` 的返回字符串里就有一处 `'…</main>\n</body>\n</html>'`，于是 probe 被塞进了 JS 字符串内部，主脚本整段 `Uncaught SyntaxError: Invalid or unexpected token`，表现成「按钮在、`exportHtmlSource is not defined`、rail 也是空的」。改成 `s.rindex('</body>')` 从后往前定位后立刻正常。教训：往导出器源码里注入测试代码，必须从文件尾部定位锚点。
- 判断「脚本到底跑没跑」不能数 `.rail-btn` 的出现次数——CSS 里也有这个类名，会得到 7 个假阳性；要看 `.rail-btn` 元素数（正确值 5）或 `typeof state`。

## 验证

headless Chrome 注入 probe（`window.load` 后跑断言，结果写 `<pre id="__probe">`，同时把导出产物落到 `<pre id="__src">` 便于落盘截图）：

- 按钮存在、导出字符串 6612 字符、含 `<main class="resume"`、`\25AA` 以反斜杠正确转义、`<title>` 为「张三 - IT 工程师（开发方向）」
- 隐藏第二条 bullet 后再导出：该条文字 `indexOf` 为 `false`（不泄漏），恢复后正常
- **round-trip**：把导出字符串喂回 `parseResumeHtml` —— 4 个模块（教育 / 项目 / 实习 / 核心技能）、姓名、求职意向、联系行、摘要 118 字全部一致；2 个项目条目；第一条项目 meta / 技术栈 / desc / 5 条 bullet 与小标题（「8 模块微服务拆分」…）逐条还原；教育时间 `20XX.09 – 20XX.06` 进 `code`；实习公司 / 岗位 / 时间齐全；技能 3 条
- **幂等**：用解析结果重建 state 再导出一次，与第一份字符串逐字节相同（`idem: true`）
- 预览未受影响：`#page` 内 13 个 li、rail 5 个按钮
- 成品目视：导出文件单独用 Chrome 打开截图（1000×1500），单页 A4、模块分割线、项目小标题、▪ 项目符号、蓝色可点击链接、加粗均与编辑器预览一致

## 已知限制

- 导出的是「一份能打开、能再导回的 HTML」，不追求像素级复刻 PDF 打印结果（打印仍走「导出 PDF」）
- 导出后若在编辑器里又改了内容，需要重新导出一次；文件之间不做同步
