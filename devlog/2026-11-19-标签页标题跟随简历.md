# 2026-11-19 标签页标题跟随简历内容

## 问题

从「打印 · 矢量」另存 PDF，保存框里的默认文件名是 `简历编辑器-拖拽排序-实时预览-导出PDF.pdf`。原因是浏览器拿 `<title>` 当默认文件名，而标题一直写死成工具的自我介绍。

工具名出现在投递件上，属于穿帮。

## 做法

标题与下载名共用一条规则，避免以后再各自漂移：

```js
function resumeFileName(){
  const pos = String((state.meta && state.meta.jobTitle) || '').split(/[｜|]/)[0].trim();
  return [(state.meta && state.meta.name) || '简历', pos, '简历'].filter(Boolean).join('-');
}
function syncDocTitle(){
  const t = resumeFileName();
  if(document.title !== t) document.title = t;
}
```

- `renderPreview()` 结尾调 `syncDocTitle()`：姓名、求职意向都是走 input → renderPreview 的链路，所以改一个字标题就跟着变，不用额外挂监听。
- `exportPdf()` 里再兜一次，避免在极端时序（刚粘完 JD/正文还没重绘）拿到旧标题。
- `<title>` 静态值从「简历编辑器 · 拖拽排序 · 实时预览 · 导出 PDF」改成「简历」，作为脚本执行前的占位；加载完成即被真实姓名覆盖。
- 三处命名收敛到 `resumeFileName()`：PDF 保存名、HTML 下载名、标签页标题（原先 PDF 与 HTML 各写了一遍拼接逻辑）。

## 验证

headless + CDP `Runtime.evaluate` 直接驱动输入框并读 `document.title`：

| 操作 | 结果 |
|---|---|
| 加载完成 | `张三-IT 工程师（开发方向）-简历` |
| 姓名改成「测试姓名」 | `测试姓名-IT 工程师（开发方向）-简历` |
| 求职意向改成「AI 应用工程师 ｜ 接受出差」 | `测试姓名-AI 应用工程师-简历`（`｜` 之后的部分按规则丢掉） |
| `title === resumeFileName()` | true |

## 踩到的坑

第一次探测报 `resumeFileName is not defined`，一度以为函数声明没落到全局。实际是 `document.readyState` 还停在 `loading`：内联脚本排在两支 jsDelivr 的 CDN `<script>` 之后，网络慢时主脚本还没开始执行。探测里加了「最多等 20 秒直到 `typeof state !== 'undefined'`」再断言，问题消失。以后验证这个工具都按这个等待策略，别按固定 sleep 猜。
