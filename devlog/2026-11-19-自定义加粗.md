# 自定义加粗字段

日期：2026-11-19
文件：`简历编辑器.html`

## 需求

简历正文原来只有「小标题（label）」会自动加粗，其他文字一律同字重。用户希望能自己指定**任意片段**加粗，且加粗要跟着进预览、PDF 导出和截图。

## 实现

用 Markdown 式 `**文字**` 作为存储格式（存进 state、导出配置、导入 HTML 后回读都不会丢），渲染时转成 `<strong>`。

- **渲染层**：新增 `richText(text)`（在 `linkify` 之后）。按 `/\*\*(.+?)\*\*/g` 切段，奇数段包 `<strong>`，各段仍走 `linkify`，所以链接识别与转义不变；没有 `**` 时直接 `linkify(s)`，零开销。
- **接入渲染**：8 处 `linkify(` 全部换成 `richText(`（联系行、个人摘要、教育行、项目 meta、项目 bullet、实习 bullet、列表项、纯段落项）。
- **编辑入口**：`area()` 的 label 行改成 `.f-head`（label 左、`B` 按钮右），按钮带 `data-bold="<path>"`。
- **CSS**：`.f-head`（flex 两端对齐）、`.bold-btn`（22×20 小按钮，Georgia 粗体 B）、`#page strong{font-weight:700;color:var(--accent-strong)}`（与 `.r-strong` 观感一致）。
- **点击逻辑**：`editorEl` 上新增 `click` 委托。取目标 textarea 的 `selectionStart/End`，空选提示「先选中要加粗的文字」；已包 `**` 则脱壳，否则包裹；改完 `dispatchEvent(new Event('input'))` 复用原有 input 链路（只 `renderPreview()`，不重建编辑器，焦点和选区都保住）。
- **导入 HTML**：新增 `richTxt(el)`——克隆节点后把 `<strong>/<b>` 替换成 `**文字**` 再取文本；用在 `liItem`、`meta.summary` 两处、`it.desc` 两处、教育行 text、纯段落 text，导入后加粗还能继续编辑。
- **说明区**补一行用法提示：选中点 B，或手写 `**文字**`。

## 验证

无头 Chrome 真实 DOM 链路（真点按钮、真读 preview 的 innerHTML）：

| 检查 | 结果 |
|---|---|
| `richText('前置**加粗**后置')` | `前置<strong>加粗</strong>后置` |
| 未闭合 `**未闭合` | 原样返回，不吞字 |
| `**https://a.com**` | `<strong><a class="r-a" …>https://a.com</a></strong>` |
| B 按钮存在 | 是 |
| 选中「加粗」点 B | `AAAA**加粗**BBBB` |
| 预览 | 出现 `<strong>加粗</strong>` |
| 再点一次（选区含 `**`） | `AAAA加粗BBBB`（脱壳） |
| 脱壳后预览 | `<strong>` 消失 |
| 项目 bullet 写 `A**B**C` | 预览渲染为 `A<strong>B</strong>C` |
| 导入含 `<strong>` 的项目简介 | `简介**加粗简介**结尾` |
| 导入 `<li><strong>小标题</strong>：正文<strong>内嵌</strong>粗` | label=`小标题`、text=`正文**内嵌**粗` |

截图确认左栏个人摘要 label 右侧出现 B 按钮，其余多行输入框一致。

## 取舍

- 不配对的 `**` 原样显示（不猜测用户意图半包），选中后点 B 时若选区已带 `**` 直接脱壳，避免出现 `****`。
- 加粗段内仍会识别链接（`linkify` 在 `<strong>` 里跑），但不再支持「加粗套加粗」——简单标记够用，也避免出现歧义解析。
- 联系行是「下拉 + 单行输入」的条目结构，不提供 B 按钮（联系信息不需要局部加粗）。
